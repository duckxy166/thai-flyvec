# บันทึกสำหรับร่างเอกสารวิจัย

รวมประเด็นจากการนำเสนอวันที่ 19 พ.ย. 2569 และผลที่ได้หลังเขียน `docs/report.md` ไว้ใช้ตอนร่างเอกสารวิจัยฉบับต่อไป ผลในหัวข้อ 3 ใช้ seed เดียว ยังไม่ได้อยู่ในรายงาน

## 1. ข้อเสนอแนะจากอาจารย์

embedding แต่ละวิธีมีโครงสร้างที่ทำให้เก่งคนละอย่าง เช่น fastText เพิ่ม character n-gram จึงรับมือคำหายากและคำสะกดผิดได้ดีกว่า word2vec ควรตอบให้ได้ว่า FlyVec เก่งงานและข้อมูลแบบไหน โดยเฉพาะกับภาษาไทยซึ่งต่างจากข้อมูลภาษาอังกฤษของงานต้นฉบับ

## 2. ใช้ชุดข้อมูลของงานต้นฉบับกับภาษาไทยได้ไหม

### 2.1 ชุดข้อมูลและผลจากงานต้นฉบับ (Liang et al., ICLR 2021 — arXiv:2101.06887)

TH-SimLex-999 และ TH-WordSim-353 (Netisopakul et al., 2019) แปลมาจาก SimLex-999 และ WordSim-353 โดยให้ผู้ใช้ภาษาไทยให้คะแนนใหม่ทุกคู่ งานต้นฉบับเทรนบน **OpenWebText** (32 GB, ~6,000 ล้านโทเคน, `N_voc = 20,000`, `K = 400`, `w = 11`, `15 epochs`) และประเมินบนชุดข้อมูลต่อไปนี้:

| กลุ่มงาน | ชุดข้อมูลในงานต้นฉบับ | ผลเด่นของ FlyVec เทียบ baseline |
|---|---|---|
| Static Word Similarity (`k = 51` vs 300d, Table 1) | WS353, MEN, SimLex-999, RW (Rare Words), RG-65, Mturk | ใกล้ GloVe บนความเกี่ยวข้อง (WS353 63.7 vs 64.0, word2vec 66.5) แต่อ่อนชัดบน SimLex (21.0 vs word2vec 41.7) และ RW (39.4 vs word2vec 61.3) |
| Binarized Word Similarity (`k = 4, 8`, Table 2 & 8) | ชุดเดียวกับด้านบน เทียบ LSH, RandExp, ITQ, SH, PCAH, NLB | **ชนะ binarized word2vec/GloVe ที่รหัสสั้น `k = 4, 8`** บน WS353 (`k=4`: 43.2 vs LSH 26.0) และ Mturk (`k=4`: 44.0 vs LSH 33.1) แต่แพ้เมื่อ `k ≥ 32–128` |
| Word-in-Context / WSD (Table 3–4) | WiC, SCWS | บน WiC (`w = 21`) ได้ **57.7%** **ชนะ word2vec (51.3%) +6.4%**, GloVe (54.9%), Word2Sense (56.5%) และแพ้ BERT-large (61.2%) เพียง 3.5% |
| Document Classification (Table 5, TextCNN `k = 30`) | 20 Newsgroups, WOS-11967, TREC-6, SST-2 | **เก่งงานแยกหัวข้อ:** 20 Newsgroups 78.2% ชนะ word2vec (77.3%) และใกล้ BERT (78.6%); **อ่อนบน sentiment:** SST-2 77.1% vs word2vec 80.7%, BERT 90.8% |
| Word Clustering (Section 3.2, Fig. 3) | Agglomerative clustering บนคลังศัพท์ | คลัสเตอร์แน่นกว่าและแยกขาดกว่า GloVe แบบ continuous |

### 2.2 ข้อจำกัดของการแปล

1. **คะแนนความคล้ายต้องให้ผู้ใช้ภาษาไทยให้ใหม่** ความหมายเปลี่ยนเมื่อแปล เช่น *cup* และ *mug* แปลเป็น "แก้ว" ได้ทั้งคู่ หรือ *rice* แตกเป็น ข้าว / ข้าวสาร / ข้าวสวย การแปลด้วยเครื่องแล้วใช้คะแนนภาษาอังกฤษเดิมจึงไม่ถูกต้อง
2. **คำแปลมักอยู่นอกคลังศัพท์** คำแปลหลายคำเป็นวลีหลายคำหลังตัดคำ ชุดที่ใช้อยู่ก็มีคู่คำนอกคลังศัพท์ 26–40% แล้ว
3. **ชุดคำหายากแปลไม่ได้ผล** คำหายากในภาษาอังกฤษอาจกลายเป็นคำทั่วไปหรือคำทับศัพท์ในภาษาไทย

### 2.3 ความเหมาะสมของการแปลแต่ละชนิดข้อมูล

| ชนิดข้อมูล | แปลได้ไหม | เหตุผล |
|---|---|---|
| คู่คำและคะแนนความคล้าย | ได้ ถ้าให้ผู้ใช้ภาษาไทยให้คะแนนใหม่ | คะแนนขึ้นกับภาษาและวัฒนธรรม |
| จัดหมวดเอกสาร | ใช้ได้ค่อนข้างดี | หมวดของเอกสารไม่เปลี่ยนตามภาษา แต่ภาษาแปลไม่เป็นธรรมชาติ ควรใช้ข้อมูลไทยจริงก่อน เช่น prachathai-67k |
| คลังข้อความสำหรับเทรน | ไม่ควร | โมเดลจะเรียนภาษาแปล (*translationese*) แทนภาษาไทยที่ใช้จริง และเกิดอคติการแปลซ้ำซ้อนกับชุดทดสอบ (บันทึกไว้ใน `docs/decisions.md` D1 และ `docs/report.md` 3.1) |

### 2.4 ข้อเสนอ: ทำซ้ำกับภาษาอังกฤษที่ขนาดเท่ากัน

แทนการแปลชุดทดสอบ ให้รัน pipeline เดิมกับภาษาอังกฤษเพื่อแยกผลของภาษาออกจากผลของขนาดข้อมูล

- คลังข้อความ: English Wikipedia ราว 10 ล้านโทเคน
- ตั้งค่าเหมือนการทดลองหลัก: คลังศัพท์ 20,000 คำ, 400 เซลล์, w = 5 / 11 / 15, learning rate 0.3, 3 epoch, 3 seed
- ชุดทดสอบ: SimLex-999 และ WordSim-353 รุ่นภาษาอังกฤษ
- baseline: word2vec, fastText และ word2vec ไบนารีที่ k เดียวกัน
- ตัวชี้วัดหลัก: สัดส่วน ρ ของ FlyVec ต่อ word2vec ในแต่ละภาษา (ภาษาไทยตอนนี้ 74–76% ที่ w = 11)

ถ้าสัดส่วนของสองภาษาใกล้กัน แปลว่าช่องว่างกับ word2vec มาจากขนาดข้อมูลมากกว่าภาษา

### 2.5 ร่างย่อหน้า "งานต่อไป"

> ชุดทดสอบความคล้ายของคำภาษาไทยที่ใช้แปลมาจากชุดเดียวกับที่งานต้นฉบับใช้ และผ่านการให้คะแนนใหม่โดยผู้ใช้ภาษาไทย แต่ยังไม่สามารถเทียบผลระหว่างสองภาษาได้โดยตรง เนื่องจากขนาดคลังข้อความและชุดทดสอบต่างกัน งานต่อไปจึงควรรัน pipeline เดียวกันกับคลังข้อความภาษาอังกฤษขนาดเท่ากันเพื่อแยกผลของภาษาออกจากผลของขนาดข้อมูล ส่วนการแปลชุดข้อมูลอื่นของงานต้นฉบับเป็นภาษาไทย เหมาะกับงานจัดหมวดเอกสารมากกว่าชุดคะแนนความคล้าย ซึ่งต้องให้ผู้ใช้ภาษาไทยให้คะแนนใหม่ทั้งหมด

## 3. ผลที่ได้หลังเขียนรายงาน (seed 0, w = 11)

| เรื่อง | ผล |
|---|---|
| learning rate ต่ำกว่า 0.3 | ρ SimLex เฉลี่ยทุก k: 0.358 (0.3), 0.336 (0.1), 0.316 (0.03) ค่าที่ต่ำกว่า 0.3 ไม่ได้ดีกว่า |
| เทรน 10 epoch แทน 3 | FlyVec ดีขึ้นเล็กน้อย (WordSim 0.389 → 0.421, SimLex 0.358 → 0.362) แต่ word2vec ดีขึ้นมากกว่า ช่องว่างไม่แคบลง |
| Wikipedia ทั้งหมด (159,719 บทความ, 71.2 ล้านโทเคน) | ρ เฉลี่ยทุก k: SimLex 0.361 → 0.406 (738 คู่), WordSim 0.389 → 0.415 (212 คู่); k = 64 ดีขึ้นมากที่สุด (SimLex 0.332 → 0.439) |
| คำที่มีเซลล์ตอบรับไม่ถึง 32 เซลล์ | 7,783 คำ (10 ล้าน) → 932 คำ (71 ล้าน) อธิบายได้ว่าทำไม k สูงแย่ลงเมื่อข้อมูลน้อย |
| การใช้เซลล์ (หน้าต่างสุ่ม 2 ล้านหน้าต่าง, น้ำหนักหลังเทรน) | ไม่มีเซลล์ไหนไม่เคยชนะ แต่ 33 จาก 400 เซลล์ชนะครึ่งหนึ่ง เซลล์อันดับ 1 ชนะ 12.2% (ส่วนแบ่งเท่ากันคือ 0.25%) เซลล์ที่เหลือถนัดหัวข้อเฉพาะ เช่น เคมี ของมีคม วันที่ |
| sentiment แยกประเภท (k = 32, ชุดทดสอบ 2,671 ข้อความ) | recall: กลาง 0.82, ลบ 0.50, บวก 0.29, คำถาม 0.05 (คำถามมีแค่ 57 ข้อความ); ทายกลางทุกข้อได้ accuracy 0.544 แต่ macro-F1 0.176 |
| ความหมายจากการใช้คำจริง | "คม" ใน Wikipedia มักเป็นชิ้นส่วนของชื่อ เช่น "ไทยคม" (367 ครั้ง) โมเดลจึงโยง "คม" กับดาวเทียมและโทรทัศน์มากกว่าของมีคม |
